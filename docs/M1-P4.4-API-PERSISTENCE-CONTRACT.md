# M1-P4.4 Phase 6 — API / Persistence Contract for Dev Teams

## 1. New endpoints (M1-P4.4)

### `GET /api/v1/diagnostics/store-hygiene` 🔒
Read-only dry-run retention report. Never mutates.

Response (abridged):

                      "eligibleCount": 1710, "eligibleIds": ["…"],

### `POST /api/v1/diagnostics/store-hygiene/cleanup` 🔒
Executes the cleanup. **Requires `{ "apply": true }`** — any other body →
`400 {error, hint}` and NOTHING is deleted. Deletes: stale mission shells
(`created`, no session, no iterations, >7d), terminal test/demo debris
(>30d, name/objective matches gate/smoke/p42 patterns), replay runs over cap
(oldest first, floor keeps most recent 400), ux assessments over cap,
zero-degree evidence nodes over cap. **Never deletes:** findings, non-terminal
missions, linked evidence, sessions (separate budget).

### `GET /api/v1/diagnostics/artifacts/orphans` 🔒
Read-only orphan-artifact report: `{totalDirs, referenced, orphanCount,
orphanBytes, unreadableCount, unreadable[], note, analysisMs}`.

### `POST /api/v1/diagnostics/artifacts/cleanup` 🔒
Deletes orphan artifact dirs. **Requires `{ "apply": true }`**. Response:
`{deletedCount, reclaimedBytes, failed[]}`.

🔒 = `Authorization: Bearer <QASE_API_TOKEN>` (401 without).

## 2. Pagination contract (unchanged from P4.3 — restated)

Applies to `GET /api/findings`, `/api/missions`, `/api/workflows`,
`/api/test-cases`, `/api/sessions`:

- **No `?limit`** → full JSON array (backward compatible, exactly the
  pre-P4.3 shape). Large (missions today: ~10 MB).
- **`?limit=N`** → envelope:
  ```json
  { "items": [ … up to N … ], "total": 3529, "limit": 5, "offset": 0 }
  ```
  - `limit` clamped to ≤ 500; invalid `limit` → treated as 10.
  - `offset` slices after stable ordering.
  - Ordering: missions/findings/sessions newest-first (updatedAt / severity
    for findings' default), workflows/test-cases insertion order (stable).
  - `hasMore` is NOT included — derive `offset + limit < total`.

Evidence endpoints (`/api/v1/missions/:id/evidence`, sessions' observations)
already return `{items, total, limit, offset}` envelopes (M1-P3).

**Frontend rule of thumb:** the SPA still uses unpaginated reads on
`/api/findings` for the bugs page (2,970 cards) — safe but heavy; new UI
code should prefer `?limit=`.

## 3. Shutdown behavior change (operators)

SIGTERM/SIGTERM now logs one line per store:
```
[shutdown] flushed: sessions
[shutdown] store flush complete in 110ms — 1 flushed, 12 clean, 0 failed
```
A store flush failure is logged `flush-failed: <name> — <error>` and DOES
NOT block the remaining stores or the exit. Second signal → immediate exit 1.

## 4. Persistence failure semantics (post-P4.4)

On load, a corrupt store file is renamed `<file>.corrupt-<epoch>` and the
store starts empty — the corrupt bytes are preserved for forensics and are
NEVER overwritten by a fresh empty write. Boot continues even if multiple
stores are corrupt (single-store isolation).

## 5. Compatibility promises

- Every pre-existing endpoint shape is unchanged (P4.3 envelope is opt-in
  via `?limit`).
- New diagnostics are additive; no existing route moved or removed.
- `deleteMission` (used by cleanup) is the same function the
  `DELETE /api/missions/:id` route uses — same side-effects (governor slot
  release, event emission), same idempotency.
