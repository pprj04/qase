# M1-P4.4 Phase 8 — Performance Measurements

All measurements on the live dev container (Node v20.20.2), stores at
2026-08-24 sizes: evidence-graph 31.25 MB / 41,664 nodes; missions 13.0 MB /
2,627; sessions 11.3 MB / 50; findings 8.9 MB / 3,768; artifacts 345 MB /
4,308 dirs.

## API response times (curl time_total, 2 runs each)

| Endpoint | Time |
|---|---|
| GET /api/health | 1.4–1.6 ms |
| GET /api/missions?limit=10 | 2.9–3.0 ms |
| GET /api/findings?limit=10 | 4.0–4.2 ms |
| GET /api/v1/diagnostics/state-integrity | 10–12 ms |
| GET /api/v1/diagnostics/store-hygiene (dry-run, full analysis) | 475–584 ms |
| GET /api/v1/diagnostics/artifacts/orphans (4,308 dirs scanned) | 877–922 ms |

## Store write cost (parse + serialize + full-file write)

| Store | Parse | Serialize+write | Output size |
|---|---|---|---|
| missions.json | 79 ms | 100 ms | 12.5 MB |
| findings.json | 43 ms | 71 ms | 8.9 MB |
| sessions.json | 57 ms | 118 ms | 12.9 MB |
| evidence-graph.json | 210 ms | 223 ms | 29.9 MB (compact) |

→ A debounced flush costs 71–223 ms per store; the P4.4 shutdown flush of
ALL dirty stores measured **110 ms total** on a clean run (only sessions
dirty) and would worst-case ~700 ms if every store were simultaneously dirty.
Both are far below any plausible shutdown-timeout budget. **Conclusion: no
persistence optimization needed — costs are linear-but-small; the fix was
correctness (flush-on-shutdown, corrupt preservation), not speed.**

## Memory

Server RSS: **230 MB** steady state with all stores loaded.

## Cleanup cost

- store-hygiene dry-run analysis: ~0.5 s (dominated by JSON.stringify of
  eligible mission records).
- artifacts orphan scan: ~0.9 s (readdir + stat + per-dir byte walk of 4,308
  dirs). Deletion itself is I/O-bound `rm -rf` and unmeasured (not applied
  yet — left for the operator; measured in test suite on scratch dirs).

## Before/after comparison

P4.4 introduced NO new hot-path work: the dirty-flag checks are O(1) per
mutation, shutdown flush runs once per signal, hygiene/artifact analysis is
behind opt-in diagnostic endpoints. No regression measurable — /api/health,
paginated reads, and evidence parse (210 ms, was 319 ms on 2026-08-23 at
38k nodes — consistent with size growth, not slower code).
