## 2. Shared mechanisms

- **atomicWrite.js** — `writeFileSync(path.tmp)` + `renameSync` = atomic on same fs. Used by ALL stores except evidenceGraph (own inline copy). Sound.
- **Debounced saves** — 11 stores use 250–500 ms timers. `unref?.()` only on sessions timer; others keep the event loop referenced.
- **No flush-on-shutdown registry exists.** knowledge.js `_flushSync()`, findings `persistFindingsSoon()`, workflows/testCases/scheduler `save*Raw()`, sessions `persistSessionsNow()` exist individually but **nothing calls them at shutdown**.

## 3. Shutdown behavior (server/index.js:2891–2904)

```js
for (const signal of ['SIGINT', 'SIGTERM']) {
  process.on(signal, async () => {
    if (shuttingDown) process.exit(1);
    shuttingDown = true;
    await Promise.all(listSessions().map(s => { liveFor(s.id).controller?.abort(); return closeBrowser(s.id); }));
    process.exit(0);   // ← debounced writes ≤500 ms old are LOST
  });
}
```

**P0 FINDING:** no store is flushed. Any mission created <500 ms before SIGTERM, any finding synced, any evidence node added in the last debounce window is silently lost. The abort/close of browsers is correct; the persistence layer is simply forgotten.

## 4. Restart / recovery semantics (current)

1. `loadSessions()` — sessions.json; running→interrupted.
2. `loadMissionsFromDisk()` — missions.json.
3. `recoverInterruptedMissions(getSession)` — running mission w/o live session → `interrupted` (M1-P3 P0-4).
4. fixValidation boot reaper — in-flight validations → FAILED `interrupted_by_restart` (M1-P3 P0-2).
5. Governor requeue — persisted `queued` missions resubmitted FIFO (M1-P4.2 Phase 6).
6. One-time migrations: ensureDefaultProject, assignOrphanedEntities, migrateFromSessions.

No recovery exists for: findings, evidence graph, replay runs, ux assessments (they simply load or start empty).

## 5. Orphan / dangling-reference risks

- **Session pruning (by design)** → 3,249 FINDING_SESSION_MISSING + 415 MISSION_SESSION_MISSING (INFO, expected — verified by stateIntegrity 2026-08-23).
- **findings.evidenceRefs** → WorkflowStep IDs (P4.3 finding), not evidence-graph node IDs.
- **Replay runs** reference `artifacts/<runId>/` dirs — artifact deletion must consult replay-runs.json.
- **Baselines** reference `artifacts/baselines/<id>/` — baselines.json is an index; dirs hold PNGs.
- **Evidence graph** `linkEvidenceToFinding` edges reference finding IDs; deleted findings leave dead edges (INFO).
- **Artifacts of deleted sessions/missions** — nothing tracks reverse references; the only liveness signal is replay-runs/baselines references.

## 6. API payload-size risks

- `GET /api/missions` (no limit) → 10.4 MB JSON in one response (P4.3 added `?limit` envelope; default remains full array for backward compat).
- `GET /api/findings` — same pattern; bugs page renders 2,970 cards from one fetch.
- `GET /api/sessions` — newest-50 only (bounded by prune).
- Evidence/observations endpoints paginate (M1-P3 P1-1/2).

## 7. Write-frequency hot spots

- sessions.json (11 MB) re-serialized on **every message append** (250 ms debounce collapses bursts, but a chatty agent turn still writes a full 11 MB file repeatedly).
- evidence-graph.json (31 MB) written on every evidence + edge batch.
- missions.json on every status transition of every mission.
