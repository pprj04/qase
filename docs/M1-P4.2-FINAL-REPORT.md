## 3. Governor architecture

- **Slot model:** 1 slot = 1 session + Chromium + LLM conversation. Default
  limit 3 (matches DEFAULTS and the observed safe envelope on 6GB).
- **Queue:** FIFO, insertion-ordered, stable 1-based positions. The start
  closure travels WITH the queue entry (`starts` map) — promotion always
  invokes the queued mission's own start, never whichever callback happened
  to be registered last.
- **Pump:** exactly one grant per release; a crashed promotion is contained
  (slot released, mission forgotten, next queued mission tried) so one bad
  mission cannot wedge the queue.
- **Watchdog sweep (every 30s):** (1) reconciles held slots against mission
  status from ANY writer (finalizers, stop handler, reaper) — terminal ⇒
  release; (2) wall-clock hard cap `missionTimeoutMinutes` ⇒ onTimeout
  (terminal `timeout` status) + immediate release even if the handler fails;
  (3) stuck detector — mission says running but its session settled ≥90s ago
  ⇒ honesty finalizer (finalize from what actually happened).
- **Idempotency:** duplicate submission returns `already-tracked`; a mission
  is either active or queued, never both.

## 4. Cancellation through the governor

- QUEUED mission + stop ⇒ `cancelled_before_execution`, never executes.
- RUNNING mission + stop ⇒ existing abort controller + browser teardown +
  terminal `aborted`, slot released immediately so the queue pumps (the
  watchdog would also catch it within 30s).

## 5. Restart recovery semantics

- Boot: running missions with lost sessions → `interrupted`
  (`session_lost_before_finalization`) via M1-P4.1's reaper; persisted
  `queued` missions are re-submitted to the governor (`requeuePersistedMissions`)
  and start when slots free — a restart no longer silently strands the queue.

## 6. API / status visibility

## 10. Remaining limitations (honest)

- The governor bounds AGENT missions only; replay suites keep their own
  `concurrentRuns` pool (by design — replay is cheaper than agent missions).
- Queue is in-memory + requeue-on-boot; a crash between slot grant and
  session creation is covered by the interrupted-mission reaper.
- No priority/preemption: strictly FIFO. Fair-share scheduling across users
  is M1-P5+ territory (multi-tenancy).
- `missionTimeoutMinutes` is wall-clock per execution, not per-iteration;
  long-but-legitimate missions need the knob raised.
