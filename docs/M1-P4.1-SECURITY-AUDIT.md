# M1-P4.1 — TARGET-URL SECURITY AUDIT (Phase 0 — inspection only, no code changed)

Full trace of the target-URL lifecycle: REQUEST → mission creation → targetUrl
validation → persistence → agent/execution → browser navigation → redirects →
BrowserStack/replay → evidence/reporting.

## 1. Current validation

**One format-only helper exists and it performs no security function.**

- `extractUrl` (index.js:250–264): regex + `new URL()` parse; accepts
  `http://localhost`, `http://169.254.169.254/`, IP-literals, any parseable
  string. Used at ONE call site (chat handler index.js:454).
- `POST /api/v1/missions` (index.js:1600–1602): presence check ONLY —
  `"not a url at all %%"` is accepted with 202 today (frozen deliberately by
  api-contract/contract-baseline.test.js:168–177, which flags the future 400).
- No IP-range, scheme-security, DNS, or redirect checks anywhere.
- No `dns` module usage in the entire repo.
- Webhook blocklist (index.js:2571–2583): substring hostname match —
  simultaneously over-broad (`10.` blocks `10.example.com`) and bypassable
  (`[fd00::1]`, decimal-IP forms, octal).

## 3. SSRF risks (ranked)

- **R1** mission targetUrl → agent browser (169.254.169.254 accepted today —
  frozen as OPEN in security-detection S2, which prescribes the 400 flip).
- **R2** stored finding URLs + URLs inside finding step text re-executed later
  by fix-validation — ingest-now/navigate-later.
- **R3** test-case targetUrl + navigate steps via replay AND the cron
  scheduler (unattended re-fetch).
- **R4** LLM-chosen URLs mid-run (agent.js:393) — prompt-level guidance only.
- **R5** webhook delivery — bypassable substring blocklist.
- **R6** UX sweep auto-navigation post-finalize.
- **R7/R8** operator-set LLM/config baseUrl + QASE_WEBHOOK_URL (auth-gated,
  operator-controlled — documented, lower severity).

Internal neighbors reachable from this box: code-server :18080,
playwright-mcp :18200, MySQL :3306, metadata 169.254.169.254.

## 4. Existing protections

requireApiToken (+ timingSafeEqual) on mutations; phaseRouter gate + explicit
public-read list; agent tool allowlist (blocks shell/fs, not URL choice);
artifacts path-traversal guard; nav/idle timeouts; device validation up-front
(the exact call-site precedent to copy); BrowserStack strict mode (truth);
prompt instruction to stay off host FS (not enforced).

## 5. Missing protections

No URL validation at ingest; no re-validation at execution sinks; no IP
classification (IPv4 private/loopback/link-local, IPv6 ULA/link-local,
IPv4-mapped IPv6); no DNS resolution step (rebinding structurally unhandled);
no request interception (redirect escape); no scheme allowlist enforcement;
webhook blocklist broken both ways; no env/config allowlist concept.

## 6. Localhost dependencies that MUST keep working (product features + protected gate)

- Practice target = server origin: `http://localhost:5173/demo`
  (demoSite.js:46, index.js:2717).
- Benchmark apps 9901–9907 (scripts/serve-benchmarks.py) — flagship demos.
- Protected suites creating missions/runs on localhost targets:
  device-execution (127.0.0.1:9901/9907), execution-provenance (9901–9907),
  phase17-e2e (localhost:9901), phase18-e2e/api (9906/9907),
  phase9.2-* (9902/9903), phase9.4 (9906), phase11a findings (9901),
  contract-baseline + redteam-truth (9901), + ~30 suites with BASE localhost:5173.
- **Conclusion: a blanket private-IP block would break the product and the
  protected gate. The boundary must be an ALLOWLIST.**

## 7. Recommended enforcement boundary

1. Single reusable module `server/targetGuard.js` (parse → classify → allow),
   used at BOTH ingest (mission create/start/iterate/revalidate, chat
   extractUrl, test-case create/update) AND the execution sinks (replay
   runTestCase + navigate steps, uxSweep, bridge restore, webhooks).
2. Policy: **public HTTP/HTTPS targets allowed; loopback allowed ONLY on the
   configured local ports** (default: server port + 9901–9907, env-extensible
   `QASE_ALLOWED_LOCAL_TARGETS`); everything else private/loopback/link-local/
   reserved/metadata denied with deterministic codes.
3. IP-literal parsing via `new URL()` (WHATWG normalization defeats
   decimal/octal IPv4 encodings for free — verified below), explicit
   IPv4-in-IPv6 unwrap, IPv6 ULA/link-local/`::1` ranges.
4. Hostnames: DNS resolve (`dns.lookup all:true`), require every resolved IP
   public; failures → DNS_RESOLUTION_FAILED (no raw DNS error leaked).
   Limitation documented: TOCTOU rebinding between validate-time and
   goto-time is narrowed (not eliminated) by re-checking at navigation time —
   stated honestly in the final report.
5. Redirects: `context.route`/`page.route` interception on NAVIGATION requests
   only (subresource requests are browser-side, not readable by the agent;
   documented limitation) — classify each navigation destination, abort
   blocked ones (goto throws → mission fails with clear reason). Normal
   public→public redirects unaffected.
6. Files/functions that must change:
   - NEW server/targetGuard.js
   - index.js: mission create/start/iterate/revalidate validation + webhook
     blocklist replacement + extractUrl validation hook
   - replay.js: runTestCase pre-flight + navigate-step check + route install
   - uxSweep.js: per-page classification before goto
   - browserBridge.js: restoreSession + (agent.js:275) device-swap goto check
   - testCases.js: validate on create/update (non-empty values only)
   - tests: security-detection S2 flip + contract G3 flip (both self-prescribe
     this change) + NEW target-guard suite incl. live redirect tests
