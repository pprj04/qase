# M1-P4.4 Phase 4 — Artifact Lifecycle

## Lifecycle states

```
created ──► referenced ──► retained ──► eligible ──► deleted
(by replay/         (while any     (unreferenced   (only via POST
 baseline/           durable store   + age gate)     /diagnostics/
 evidence capture)   points at it)                  artifacts/cleanup
                                                     {apply:true})
```

| State | Meaning | Enforced by |
|---|---|---|
| created | dir written under `.qase/artifacts/<runId>/` | replay.js, baselines.js, evidence capture |
| referenced | ≥1 durable store names the dir | artifactLifecycle.collectArtifactReferences |
| retained | referenced → never eligible, regardless of age | analyzeArtifacts |
| eligible | unreferenced AND older than `orphanOlderThanDays` | analyzeArtifacts |
| deleted | rm -rf, logged with reclaimed bytes | applyArtifactsCleanup |

## What counts as a reference (exhaustive)

A dir `<name>` is referenced if ANY of:
1. any string `artifacts/<name>` appears in replay-runs.json, baselines.json,
   missions.json, findings.json, sessions.json, evidence-graph.json,
   test-cases.json, workflows.json (whole-store regex scan);
2. a replay run carries `screenshotPaths: ["<name>/shot.png"]` or
   `tracePath: "<name>/trace.zip"` (ARTIFACTS_DIR-relative bare paths);
3. a baseline entry's `artifactPath` starts with `baselines/<name>`.

## Age-gate caveat (IMPORTANT — verified on this volume)

Artifact dir mtimes are RESET to the container-restart time (volume remount;
observed 2026-08-24: every dir reports mtime == boot time, ~20,669 "days"
apparent age from epoch math is actually 0). Therefore:

- `orphanOlderThanDays` **defaults to 0** — reference-hood is the only
  trustworthy liveness signal;
- the report carries a `note` explaining this to operators.

## Current state (2026-08-24, live)

- total dirs: 4,308 · referenced: 1,438 · **orphans: 2,855 (172 MB)** ·
  unreadable (kernel-corrupt): 15 — cannot stat/enumerate; reported, never
  silently skipped; excluded from deletion (they fail rm and land in
  `failed[]`).

## Guarantees

- API references to existing artifacts remain valid: referenced dirs are
  never eligible.
- Deleting an orphan can never break a finding, mission, replay run,
  baseline, or evidence node — by definition nothing durable points at it.
- Cleanup is idempotent (re-running reports 0 orphans), fully logged
  (`[artifacts] deleted orphan …`), and only runs behind
  `requireApiToken` + `{apply:true}`.

## Known limitation

- Kernel-corrupted dirs (`Unknown system error -117`, `Structure needs
  cleaning`) cannot be removed from inside the container. They are listed in
  `unreadable[]` for the operator; a host-level fsck/volume rebuild (outside
  QASE scope) is the only remedy. NOT VERIFIED whether they hold referenced
  data — their contents cannot be enumerated.
