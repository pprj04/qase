## 3. Vulnerabilities addressed

- **R1 Mission targetUrl → page.goto (SSRF, HIGH):** `POST /api/v1/missions`
  accepted any syntactically valid URL (or none at all at some paths) and the
  agent navigated to it. Now: allowlist validation at create + re-validation at
  start/iterate/revalidate + browser-layer interception.
- **R2 Redirect-to-internal (CRITICAL, discovered live):** Playwright's
  `context.route()` **does not fire for redirect-chain navigations** — verified
  live: a 302 to `http://2852039166/` (decimal 169.254.169.254) loaded the
  metadata IP with the route handler never seeing hop 2. Fixed with a CDP
  `Fetch.requestPaused` enforcement layer (pauses every request in the chain)
  attached per page before navigation; `newPage` is patched so the attach is
  awaited before the caller can navigate (closes the enable/goto race).
- **R3 Webhook SSRF:** substring blocklist was bypassable both ways
  (blocked `10.example.com`; missed `[fd00::1]`, decimal/octal IPs). Replaced
  by `validateWebhookUrl` (same classifier).
- **R4 Fix-validation delayed-execution vector:** persisted finding/test URLs
  (mined from step text) were replayed unvalidated. Now validated before any
  attempt; blocked → honest FAILED run that can never influence fix-status.
- **R5 Legacy ingest paths:** `PUT /api/missions/:id`, `POST /api/missions/:id/link-session`,
  `POST/PUT /api/test-cases`, agent `browser_open`, uxSweep discovered pages,
  chat `extractUrl` — all now pass the same boundary.
- **Bypass matrix (Phase 6, live-probed, all 4xx):** hex/decimal/octal IPv4
  (`0x7f.0.0.1`, `2130706433`, `0177.0.0.1`, `2852039166`), IPv4-mapped IPv6,
  uppercase `LOCALHOST`, `localhost.` trailing dot, `foo.localhost`,
  userinfo tricks (`https://example.com@10.0.0.5/` — WHATWG hostname is the
  REAL host), RFC1918/CGNAT/link-local/reserved ranges, `metadata.google.internal`
  (DNS-resolved), gopher/file schemes.
  `http://10.0.0.5@evil.com/` is **ALLOWED by design** — the hostname is
  `evil.com` (public); the userinfo is not the destination.

## 4. URL validation architecture

Single module, deterministic verdicts, allowlist policy:

```
validateTargetUrl(raw) → { ok, code, message?, url? }
  codes: VALID_PUBLIC_TARGET | INVALID_URL | UNSUPPORTED_SCHEME |
         PRIVATE_NETWORK_TARGET | LOOPBACK_TARGET | LINK_LOCAL_TARGET |
         RESERVED_TARGET | DNS_RESOLUTION_FAILED | PORT_NOT_ALLOWED
```

- Parsing: WHATWG `new URL()` — normalization defeats encoded-IP forms for
  free (verified matrix in tests).
- IP classification: RFC1918, CGNAT 100.64/10, loopback (v4+v6), link-local
  (169.254/16, fe80::/10), reserved/special-use (0.0.0.0, TEST-NETs, ULA as
  PRIVATE), IPv4-mapped/compatible IPv6 delegated to v4 classifier.
- **Loopback allowlist ports:** the product's own practice target (PORT=5173)
  and benchmark apps 9901–9907 + operator extension `QASE_ALLOWED_LOCAL_TARGETS`.
  This preserves the first-class local-testing feature while closing every
  other loopback port. IPv6 loopback `::1` is ALWAYS denied (never needed as a
  practice target).
- DNS: `lookup({all:true,verbatim:true})` with 4s timeout; **every** resolved
  address re-classified (mixed public/private → denied). No raw DNS errors in
  responses; deterministic machine code + human message.
- No shell execution, no credential usage, no filesystem access.

## 5. Redirect protection

Two layers, identical classifier:
1. **Base layer** — Playwright `context.route`/`page.route`: first navigations
   (engine-portable fallback).
2. **Enforcement layer** — CDP `Fetch.requestPaused` per page: catches
   redirect-chain navigations (the layer that actually works for chains),
   installed by patching `context.newPage` so `Fetch.enable` completes before
   the caller navigates. Blocked → `Fetch.failRequest(BlockedByClient)` →
   `page.goto` rejects with `net::ERR_BLOCKED_BY_CLIENT` → callers record
   honest failures.
   Public→public redirects pass (verified live: redirector → example.com).

- **Run 2:** 1184t / 1167p / **2 fail** — phase17-api suite cancelled all 16

  timeout + 4-attempt retry in `before()`); all other suites green.
- **Run 3 (final):** 1184t / 1180p / **1 fail** — `phase9.2-revalidate-e2e`
  8t/5p/3f: E2E-3 "wait for mission to complete" hit its 1200s ceiling. Root
  cause investigated (not boundary code): the mission's session shows
  **0 messages, idle after exactly 20 min** — the turn watchdog fired during
  the first LLM turn because the provider was returning empty responses and

  **8/8 pass in 836s** (`artifacts/logs/p92-revalidate-verify.log`).

  the definitive fix (cap + queue) is the next roadmap build. 6 stale

## 9. Remaining limitations (honest)

- **DNS rebinding TOCTOU (narrowed, not eliminated):** hostname resolving
  public at validate time and private at navigation time is narrowed by
  navigation-time re-classification of IP literals + CDP interception, but a
  determined attacker controlling a domain's TTL can still race the two
  resolutions. Full mitigation requires egress IP pinning at the network layer
  (out of scope M1-P4.1; recommended M1-P5).
- **Subresource requests are not intercepted** (only Document navigations): a
  public page that `<script src>`s a private resource is the browser's own
  request; the agent never reads that body. Accepted + documented.
- **Non-Chromium engines:** CDP layer unavailable; the route base layer covers
  first navigations only (redirect chains NOT covered on Firefox/WebKit).
  QASE runs Chromium today (agent + replay + BrowserStack Chrome), so this is
  theoretical; documented.
- **Loopback allowlist ports are environment-wide**, not per-user (single-tenant
  model — consistent with the M1-P1 contract; revisit with multi-tenancy).
- Local practice ports themselves remain reachable targets BY DESIGN (that is
  the local-testing feature) — an attacker with a mission token could point a
  mission at the demo app; impact is limited to QASE's own practice surfaces.
