# D2.1 — Configurable session wall-clock timeout (QASE_SESSION_TIMEOUT_MINUTES)

## Problem (live evidence)

Mission `dc602be1` (new.drytis.com, `maxTurns: 300`): session ran 22 min wall-clock and was
aborted at turn 148/300 by the hard-coded `SESSION_TURN_TIMEOUT_MS = 20 * 60 * 1000`
(server/agent.js:37). The abort lands in the B2 "stopped without report" path →
deterministic close-out → 0 test cases, no model-authored report. Raising `maxTurns`
alone cannot fix this: the wall-clock guard always wins on real external sites.

Truthfulness wart: the close-out summary says "Run stopped at the authorized turn budget
(300 turns)" — false. The real cause was the wall-clock timeout. Two different abort
reasons currently share one label.

## Scope (one file + env)

- server/agent.js only.
- New backend env key `QASE_SESSION_TIMEOUT_MINUTES` (static, default empty = 20).
- .env.example documentation.

## Boundaries (must NOT change)

- Turn-budget authority / B2 invariant: budget N ⇒ ≤ N model turns. The wall-clock guard
  only ever SHORTENS a run; the close-out still spends zero model turns.
- Decision engine / autonomy (C2), finding quality (C3), targetGuard/SSRF, B1 auth,
  D0.5/D2 auth, Pulse/OpenAPI: untouched, not read.
- Test-case generation stays SKIPPED on timeout close-out (close-out pipeline capability
  filter unchanged — documented honestly, not "fixed").

## Changes

### A. Configurable constant (agent.js)
- Resolve `SESSION_TURN_TIMEOUT_MS` from `process.env.QASE_SESSION_TIMEOUT_MINUTES`:
  - unset / empty → 20 (today's behavior, byte-identical)
  - integer 5–120 → that many minutes
  - anything else (non-integer, <5, >120) → 20 + one-line console.warn
- Clamp rationale: 20 min was sized for ~20 turns; observed ~9s/turn ⇒ 120 min covers
  300-turn missions. Floor 5 protects against fat-finger `QASE_SESSION_TIMEOUT_MINUTES=1`.

### B. Truthful attribution (agent.js)
- `let timeoutWallClock = false;` beside `limitAborted` / `earlyStopRequested`.
- Set it inside the `turnTimeoutTimer` callback before `controller.abort()`.
- In the catch cascade, check `timeoutWallClock` BEFORE the generic
  `controller.signal.aborted → 'Stopped by user.'` branch. On timeout:
  - `session.turnCount = turnCount` (true count)
  - `session.stopCause = 'wall_clock_timeout'`
  - settle `done` (same as budget path — close-out eligible, no retry loop)
  - system message names the timeout truthfully.
- `finalizeTurnLimitedRun()` (agent.js:859): read `session.stopCause`; when
  `wall_clock_timeout`, the summary reads "Run stopped at the session wall-clock
  timeout (X min, reached at turn N of M). …" — budget-stopped runs keep the existing
  exact wording (regression-guarded by a test).

### C. Env key
- `add_environment_key` QASE_SESSION_TIMEOUT_MINUTES → /workspace/.env (static, default
  empty, description documents 5–120 clamp and default 20).
- .env.example line.

## Tests — tests-real/session-timeout.test.js (new)
