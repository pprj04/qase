## Design

Device request model (normalized at API boundary, validated → 400):
`'iPhone 15 Pro' | { device, browser?, browserVersion?, os?, osVersion? }`.
Class strings map deterministically: mobile → iPhone 15, tablet → iPad Pro 11
(DEFAULT_DEVICE_BY_CLASS). desktop/none/'' → null (desktop, unchanged).

Truth taxonomy (executionModeFor, computed from env — never from viewport):
- VIEWPORT        local, device null,  engineEmulated false
- EMULATED_DEVICE local, device set,   engineEmulated true
- REAL_DEVICE     browserstack, device set, engineEmulated false
- CLOUD_DESKTOP   browserstack, device null (BS desktop browser)

Provider selection stays config-driven: BS enabled ⇒ device runs on BS real
hardware (REAL_DEVICE); BS disabled ⇒ local Chromium emulation
(EMULATED_DEVICE). A mobile viewport is NEVER a device claim.

BrowserStack real devices: BROWSERSTACK_REAL_DEVICES = Pixel 8/7/5,
Galaxy S9+ (caps: os android, device '<BS canonical>', real_mobile true,
browser chrome). iOS real devices are NOT supported by the BS Playwright
CDP path → deterministic 'Unsupported device configuration: …' (no
substitution, no downgrade, no local fallback). Non-chrome browser + device
on BS → same deterministic unsupported error.

Validation boundaries: POST /api/sessions {deviceRequest}, POST /v1/missions
constraints.device, POST /api/test-cases/:id/run + /api/test-cases/run
{device} — all 400 on unresolvable device. runTestCase internally returns a
deterministic error result (defense in depth for validation executor/suite
callers). Validation executor passes a finding's device name through ONLY
when it resolves (legacy findings with unparseable device strings behave
exactly as today — desktop — so frozen Phase 18 behavior can't regress).

Session/mission persistence: mission.constraints (existing), session.
deviceRequest (existing), session.device (existing), run.
executionEnvironment (B0.2), finding.device/environment (B0.2/B0.3). No new
store.

UI (minimal): device select gains named devices (no redesign); tests.js BS
badge gains a real-device variant (📱 device · BrowserStack · real device);
device strip already truthful.

Security: caps carry the BS key ONLY inside the wss URL (as today, B0.2);
unsupported-device errors echo only the device NAME; env objects contain no
credentials (B0.2 invariant).
