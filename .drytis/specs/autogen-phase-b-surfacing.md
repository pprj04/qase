# Phase B — API + Test Cases panel surfacing

## Goal
Users can see, filter and manage agent-generated cases in the existing Test Cases panel; manual creation flow unchanged.

## Design
- API: extend `server/testCaseApi.js` list route with `?source=auto|manual` and `?sourceRunId=` filters (server-side filter on the service list; no schema change needed since fields ride on records). POST stays manual-only (source cannot be spoofed to `auto` via public POST — force `source: 'manual'` on input).
- Badge: records with `source: 'auto'` get an "auto" pill in the panel rows (public/testCaseView.js render), with title text "Generated by agent from run <shortRunId>".
- Filter control: a small `Source: All / Manual / Agent` select next to the existing filters in the Test Cases modal; wires into the list fetch (`source` param). Default All.
- Source-run link: in the case editor/detail, when `sourceRunId` present show a "View run" action that selects that session (existing `onOpenRun`-style pattern used by deviceMatrixView).
- Regenerate affordance: a "Generate from run" action in the run report header (small button next to existing report actions) that calls a new `POST /api/test-cases/generate { runId }` reusing the Phase A generator synchronously (returns created cases; 409 if run has no report yet; respects the same dedup rules — already-generated cases are not duplicated).

## Files
- `server/testCaseApi.js`, `server/testCaseApi.test.js`
- `server/testCaseService.js` (force manual source on POST)
- `public/testCaseView.js`, `public/testCaseView.test.js`, `public/index.html` (filter select + auto pill markup), `public/styles.css` (pill + button styles, reuse existing badge language)
- `public/app.js` (report header "Generate from run" action)

## Acceptance criteria
- [ ] List `?source=auto` returns only generated cases; `manual` only manual ones; default returns all
- [ ] Public POST cannot create `source: 'auto'` records
- [ ] Panel shows an "auto" badge on generated cases with run tooltip
- [ ] Source filter All/Manual/Agent works in the panel
- [ ] "View run" on a generated case opens that run in the app
- [ ] "Generate from run" on a completed run creates cases immediately; clicking twice does not duplicate
- [ ] Manual create/edit/delete flows unchanged
- [ ] Tests: API filter + spoof protection; view badge/filter rendering; generate endpoint dedup
