Status: in progress · Scope: BS config truthfulness ONLY (no device execution, no provenance, no strict-fallback mode, no dead-code cleanup, no deploy).

## Inspection findings (what exists)

1. `server/config.js` — merge order `[fromEnv(), readStored()]`: **env wins whenever it has a non-empty value**, even when Settings stored its own value. `saveConfig` handles `browserstackUser/Key` only as non-empty string writes (same loop as apiKey) — an empty-string clear is IGNORED for BS keys (only `apiToken` supports explicit clear). No `lastVerified` concept.
2. `server/replay.js:78–97` — BS CDP launch with silent fallback (untouched in this build).
3. `POST /api/config/test` → `testConnection()` probes ONLY the LLM `${baseUrl}/models`. No BS probe exists anywhere.
4. Settings UI (`public/app.js` cfg map + `public/index.html` BrowserStack section): enable/browsers/user/key + Clear button already wired; key never sent back to browser (blank-keeps + placeholder hint). No BS test button.
5. `.env` currently: `QASE_BROWSERSTACK_ENABLED="\"false\""` (double-quoted), USER/KEY = known placeholder garbage. `.qase/config.json`: stored user 'tRuEje…', key EMPTY, enabled false.

**Flip-flop root cause (proven):** env garbage key + empty stored key → env wins on every boot → garbage creds become effective whenever BS is enabled; and Settings can never clear them because saveConfig ignores empty-string clears for BS fields. procmgr restarts re-expose the env values each time.

## Implementation plan

### Item 1 — `server/browserstackTest.js` (new, injectable)
`testBrowserstackConnection({ user, key, timeoutMs, fetchImpl, nowImpl })`:
- Missing creds → `{ ok:false, error:'BrowserStack username and access key are required.' , code:'missing_credentials'}`.
- Real auth probe: `GET https://api.browserstack.com/automate/plan.json` with HTTP Basic auth (BrowserStack's documented lightweight authenticated endpoint), 10s timeout. 401 → invalid credentials (actionable message). Network error/timeout → connectivity failure message. 2xx → authenticated.
- Then a CDP reachability probe: `wss://cdp.browserstack.com/playwright` WebSocket handshake with caps (no page opened) — reported as separate `cdp` sub-result; CDP failure doesn't fail auth but is surfaced.
- Returns `{ ok, code, message, user (maskable), lastVerifiedTs, auth:{...}, cdp:{...} }`. **Never includes the key.** `fetchImpl` injectable for tests; default global fetch.
- `maskUser(u)` helper → `use****XYZ`.

### Item 2 — route + config fields
`POST /api/config/test-browserstack` (requireApiToken) in `server/index.js` next to `/api/config/test`:
- Body may carry `browserstackUser/browserstackKey` (from unsaved Settings) — falls back to effective config when absent/blank.
- On success AND on explicit test failure, persist `browserstackLastVerified = { ts, ok, code, message }` via a new `saveConfig` path (no key written; message stored is the redacted message).
- Response: full probe result minus key.

### Item 3 — config authority fix (`server/config.js`)
- Merge for BrowserStack credential fields ONLY: **stored value beats env when present** (BS-specific invert: `browserstackUser`, `browserstackKey`). Env still seeds when stored is empty (bootstrap behavior preserved). All other fields unchanged.
- `saveConfig`: allow explicit clear of `browserstackUser/browserstackKey` when empty string AND `dataset.cleared`-style explicit-clear semantics: add `clearBrowserstackKey`/`clearBrowserstackUser` patch flags? Simpler + backward compatible: treat empty-string patch as "clear" for browserstackUser/Key (matching apiToken semantics) — the UI only sends empty when Clear was pressed (verified in readSettings: patch.browserstackKey='' only when cleared flag set).
- `getPublicConfig`: add `browserstackLastVerified` (ts/ok/code/message — no secrets).

### Item 4 — Settings UI
- Button `Test BrowserStack Connection` next to key Clear (existing `.test-result` styling conventions).
- Shows: ✓ Connected / ✕ Failed, masked user (`use****XYZ`), last verified time (`toLocaleString`), actionable error.
- Sends unsaved field values (same pattern as LLM test button via readSettings()).

### Item 5 — tests `tests/browserstack-trust.test.js`
Injectable fetchImpl — no real network:
1. valid creds → auth 200 → ok:true, no key in JSON.stringify(result).
2. invalid creds → 401 → ok:false + actionable message.
3. malformed (empty/whitespace) → missing_credentials without network call.
4. timeout (fetchImpl hangs past timeoutMs) → ok:false timeout message, resolves.
5. network failure → connectivity message.
6. persistence: saveConfig with BS creds → config.json on disk keeps them after `stored` cache reset (simulating restart) → getConfig still returns stored value even with conflicting env values set.
7. clear semantics: saveConfig({browserstackKey:''}) clears stored key (env no longer effective when nothing stored).
8. endpoint auth protection: POST /api/config/test-browserstack without token → 401 (live server, like phase18-api pattern).
9. getPublicConfig never contains key material (hint only).
