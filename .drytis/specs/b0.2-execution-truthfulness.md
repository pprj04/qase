## Inspection findings (what already exists)

1. **replay.js `launchBrowser()`** (lines 75–112): single browser factory.
   BrowserStack path when `config.browserstackEnabled && user && key` —
   `chromium.connectOverCDP(wss://cdp.browserstack.com/playwright?caps=…)`;
   on ANY failure: `console.warn('falling back to local')` → local Chromium.
   **SILENT FALLBACK — the core untruth.** Returns only the browser object;
   no provider metadata. Caller: `runTestCase()` line 541 (sole call site).
2. **`runTestCase()`** result object (lines 519–535): `viewport` (resolved),
   `browser: browserType || 'chromium'` — the REQUESTED browser label, not
   the executed engine. No provider, no executedOn, no OS, no device.
3. **`runTestSuite()`** summary.results inherit the same shape; `browsers`
   list expansion multiplies by requested-browser labels.
4. **validationExecutorCore.js** calls `runTestCase` directly (2 sites) and
   copies `res.result`/`error`/`assertions`/`steps` into attempt records —
   no environment capture. `computeEnvironmentDeltas` compares plan vs
   finding but `plan.browser` baseline is `null`.
5. **findings.js `addFinding`/`syncSessionFinding`**: NO device field today;
   qaTools.js `report_finding` tool (session findings source) has no
   environment info either; session.device exists only for agent missions
   with deviceRequest.
6. **evidenceGraph.js `createEvidence`**: has `metadata` free-form object —
   provenance can ride there WITHOUT schema changes (B0.1-verified pattern).
7. **deviceContext.js**: `buildDeviceContext` already computes `engine`,
   `engineRequested`, `engineEmulated`, `os`, `browser`, `viewport`,
   `deviceScaleFactor` — local device emulation truth exists at the mission
   layer but is NOT propagated to replay results.
8. **junit.js / replayStore addRun / webhooks** consume summary/results as-is
   (additive fields flow through untouched).

## Design (all additive)

### D1. `server/executionEnvironment.js` (NEW, ~120 lines)
`buildExecutionEnvironment({ provider, browser, browserVersion, os, osVersion,
device, viewport, engineEmulated, executedOn })` →
`{ provider: 'browserstack'|'local', device, browser, browserVersion, os,
osVersion, viewport: {width,height}, engineEmulated: boolean, executedOn:
<number ms> }` — every unknown → null. `viewport` always concrete (from
resolveViewport). `provider` MUST be 'browserstack' or 'local' (validated).
`isRealDevice(env)` helper: `provider==='browserstack' && device != null`.

### D2. replay.js `launchBrowser(opts)` → returns `{ browser, environment }`
- BrowserStack attempt: build env `{ provider:'browserstack', browser: caps
  label, os, osVersion from BROWSERSTACK_OS_MAP, browserVersion: null (CDP
  doesn't expose it), device: null, engineEmulated: false, executedOn: now }`.
  Try `browser.version()` (best-effort, null on failure).
- **STRICT MODE**: `config.browserstackStrict !== false` (default TRUE) —
  if BrowserStack connect fails → throw
  `BrowserStackStrictError('BrowserStack execution failed — local fallback
  was disabled. …')`. Only when `browserstackEnabled` is EXPLICITLY true.
- Local: `{ provider:'local', browser:'chromium', browserVersion:
  browser.version() best-effort, os: process.platform, osVersion:
  os.release(), device: opts.device ?? null, engineEmulated:
  Boolean(opts.device), executedOn: now }`.
- `launchBrowser` must stay call-site compatible: return object; the ONE
  caller (runTestCase) updates. (No other call sites — verified.)

### D3. `runTestCase()` stamps `result.executionEnvironment`
- Capture from launchBrowser's environment; viewport = the resolved vp.
- Local + viewport-only (no opts.device): `engineEmulated:false`,
  `device:null` — a desktop viewport is NOT a device.
- STRICT failure path: `result.result='error'`,
  `result.error = BrowserStackStrictError message`,
  `result.executionEnvironment = { provider:'browserstack', …, executedOn,
  failed: true }` — the run FAILS, never relabels as local.
- Fallback suppression logging: one console.error line (visible, not silent).

### D4. `runTestSuite()` stamps summary + per-result; aggregation preserves
`executionEnvironment` on aggregated spread (it comes from vr[0]).

### D5. validationExecutorCore: after each `runTestCase`, copy
`res.executionEnvironment` into the attempt record (`executionEnvironment`)
and record ONE evidence node per run (phase 'after', type OBSERVATION,
metadata.executionEnvironment). `completeRun` gains
`executedOn: Date.now()` on the run + `executionEnvironment` of final
attempt. Evidence `recordEvidence` metadata gains
`environment: buildExecutionEnvironment({...})` at the 'before' node from
plan (provider local default, unknowns null).
FROZEN: classifyFixStatus inputs unchanged (engine untouched); fixStatus
reasons unchanged; phaseRouter contract unchanged.

### D6. findings: `addFinding` accepts optional `device` + `environment`
(additive; null-safe defaults), stores only when non-null (never overwrite
existing correct value with null — sync uses `!= null` guards).
qaTools `report_finding` auto-attaches `session.device` →
`device: describeDevice(session.device)`, `environment: { provider:
'local', engineEmulated: session.device?.engineEmulated ?? false, … }` when
a device context exists. POST /api/findings passthrough unchanged (extra
fields ignored unless explicitly added).

### D7. Evidence: B0.2 adds `metadata.executionEnvironment` on validation
evidence nodes (D5). BrowserBridge/session evidence unchanged (no replay
path there — out of scope).
