# Recon: upgrading Device Matrix to real QASE-owned executables (NIHARIKA branch, 2026-10-05)

Evidence baseline for the "every matrix cell backed by a real local executable, honest Unavailable/NOT SUPPORTED + pre-execution health checks" upgrade.

Key findings (details verified by direct file reads):
- Levels SIMULATED/VIRTUAL_DEVICE/REAL_DEVICE in server/deviceRuntime/provider.js L12-23; AVAILABILITY AVAILABLE/BUSY/OFFLINE. Manager (server/deviceRuntime/manager.js) never downgrades silently; seedBoard (L360-375) marks envs OFFLINE unless a provider attests REAL/VIRTUAL. Today only providers: local-simulation (SIMULATED), browserstack (VIRTUAL/REAL, needs creds), null-real-device (supports nothing). => with no BrowserStack creds every board env is OFFLINE and executionType default is VIRTUAL_DEVICE (environmentService.js withExecutionMetadata L275-318, RUNTIME_PLACEHOLDER 'UNAVAILABLE').
- UI status source: GET /api/device-runtime/devices (app.js L599-604) → fields envId/status/maximumLevel/currentSessionId/queueLength/lastTestedAt/lastResult; rendered by public/deviceRuntimeUi.js (availabilityMeta/executionTypeLabel/fallbackOptionsFor) + deviceMatrixView.js L136-146/L388-438.
- Browsers actually in container: /usr/bin/google-chrome 151.0.7922.137 (real branded Chrome, not referenced by any code path) + Playwright builds chromium-1234 (Chrome for Testing 151), firefox-1538 (FF 153), webkit-2336 (GTK MiniBrowser under Xvfb per browserEngines.js L107-131), ffmpeg. NO edge/opera/brave/duckduckgo binaries.
- browserSupportResolution.js: static table; chrome/edge/firefox SUPPORTED locally (edge is Chromium engine-equivalent), safari ENGINE_EQUIVALENT (webkit), opera/brave ENGINE_EQUIVALENT, duckduckgo NOT_SUPPORTED. No binary probing — all static.
- Media: browserMedia.js mic only (CDP Browser.setPermission, synthetic RMS probe). No camera/screen-share probe code. Not a pre-exec health check — agent-invoked tool only.
- Tools: browserTools.js only 3 tools (security_check, browser_media, browser_test_meeting_link). Real interactions live in browserBridge wrap() of POINTER_ACTIONS click/hover/fill/check/select/uploadFiles/pressKey/scroll + typeText + open/navigateBack/navigateForward/reload/newTab. NO tap/swipe/long-press/orientation-change APIs; touch handled implicitly via context hasTouch + prompt text (deviceProfiles.js L174).
- runtimeIdentity.js parses LIVE UA (brand+engine, iOS WebKit-wrapper honesty) and verifyRuntimeIdentity blocks mismatches; runtimeFacts captured from real page at context creation (browserBridge L587/L660) and turn end (agent.js L1093-1108); persisted on runs (runtime_facts). Browser version is runtime-observed, not catalog-assumed.
- cellHeartbeat*.js = distributed "cell" infra heartbeat (queue depth metrics → control plane), NOT wired to matrix availability. capacityEvidence.js = load-test evidence normalization, unrelated. No browser/health pre-flight exists; nearest is resolveEngine availability (browserEngines.js) at launch time.
- Bulk runs: public/bulkRunView.js wizard → app.js launchPairs (L6160) loops POST /api/sessions per (case, envId) — each env DOES get its own session. Server-side replacement: matrixService.js + matrixOrchestrator.js (item statuses PENDING/RUNNING/PASSED/FAILED/NOT_RUN/UNAVAILABLE/NOT_SUPPORTED/BLOCKED/ERROR, sequential, concurrency cap 2).

Gaps for the upgrade: no branded-browser launcher (google-chrome unused), no per-cell executable health probe, no camera/screen-share testing, no touch gesture APIs, availability purely provider-capability-based (never probed), bulk wizard still client-loop vs matrix orchestrator.
